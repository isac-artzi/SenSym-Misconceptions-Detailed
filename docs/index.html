Wrong in a Particular Way

Misconception-aware prompting and the detection of structured error in cybersecurity learning

A wrong answer is not noise. Students are wrong in particular, repeatable, nameable ways, and a teacher who knows the catalogue of those ways sees things a teacher without it does not. This project asks whether the same is true of a language model — and measures it, on a laptop, with a model small enough to run for free.

The research question

Does giving a small language model an explicit catalogue of known misconceptions improve its ability to detect those misconceptions in student writing?

The domain is cybersecurity — passwords and authentication — chosen because misunderstanding there has consequences you can point at. The pilot narrows to the detection step, because detection is a precondition for corrective feedback: a tutor that cannot tell a confused answer from a correct one cannot possibly correct it.

Two conditions, identical in every respect but one. The baseline prompt asks a generic grader to judge whether a response contains a misconception. The misconception-aware prompt is the same request with the catalogue of ten specific misconceptions pasted in. Same model, same temperature, same forty responses. The only difference is what the model was told to look for.

And a third, which is the control: the decoy prompt is the same catalogue prompt carrying ten documented misconceptions about physics. It cannot help with a password answer. It exists because the misconception-aware prompt changes two things at once — the model gets a catalogue, and the prompt gets longer and more structured — and without the decoy there is no way to tell which of those did the work.

Headline expectation, stated in advance so it can be wrong: the misconception-aware condition improves recall more than precision, because naming the failure modes helps the model notice them, not helps it avoid false alarms — and it beats the decoy, because the catalogue's content matters and not merely its bulk.

What the experiment actually does

Forty responses go in. Each one is sent to the same model twice, once under each prompt, and each reply is turned into a single letter: M for "contains a misconception", C for "correct". Compare those letters to the labels you wrote, and you get a 2×2 table. Everything in Phase 5 is arithmetic on that table. Drag the slider to see how the same accuracy can hide very different tables.

Why this project is worth doing

It can be wrong

The interesting outcomes include "the catalogue did not help." A study designed so that only one answer is publishable is not a study. The prediction is written down in advance, on this page, so that it can fail.

It is reproducible

A local model at temperature 0, a fixed dataset in the repository, and a test suite that cross-checks every metric against scikit-learn. Someone else can clone this and get your numbers.

It runs on a laptop

No API key, no bill, no rate limit, and no student writing leaving the machine. If prompting alone lifts a 3-billion-parameter model, that is a result a school could actually deploy.

A note on where this sits

This is a pilot, not a finished study. Forty items is enough to detect a large effect and nowhere near enough to detect a small one — Phase 5 shows you exactly how wide the confidence intervals are, which is itself one of the more useful things to learn from running it. The honest framing of the result is "here is a method, here is what it showed at this scale, and here is what a larger version would need." That framing is not a weakness. Overclaiming is.
