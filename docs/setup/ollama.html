1 · What Ollama actually is

Two minutes of reading that makes every later error message make sense.

The single most useful thing to understand: Ollama is not an app you type questions into. It is a small program that sits in the background running a web server on your own computer. Your Python sends it a prompt over the network — except the network is your laptop talking to itself — and it sends back text. There is nothing else to it.

The whole arrangement

Three components, none of which leaves the machine. Click a box to see what breaks when that one is missing, and what the error looks like.

That address — localhost:11434 — appears in every error you will hit. localhost means "this machine." 11434 is the door number Ollama listens at. So when llm_client.py reports "Could not reach Ollama at http://localhost:11434", it is saying exactly one thing: I knocked on that door and nobody answered.

Three separate things · keep them apart

Ollama the program is installed once. The server is the background process that must be alive whenever your script runs. The model is a large file downloaded once with ollama pull.

You can have the program with no model, or a model with the server stopped. Both feel like "it's broken" and have completely different fixes. Nearly all the confusion on this step comes from collapsing these three into one.

2 · Install it

Go to ollama.com/download, take the macOS download, unzip it, and drag Ollama.app into Applications. Open it. The first launch asks permission to install the command-line tool — say yes; that is what makes the word ollama work in Terminal.

A small llama icon appears in the menu bar at the top right. That icon means the server is alive.

Good news

On macOS the app starts the server automatically and keeps it running. You do not need to babysit a terminal window. But read the box in section 3 about ollama serve before you go looking for one.

Go to ollama.com/download, take the Windows download, and run OllamaSetup.exe. Click through, then launch Ollama from the Start menu.

A llama icon appears in the system tray at the bottom right — possibly hidden behind the ^ arrow. That icon means the server is alive.

On a school-managed laptop

The Windows installer writes into your own user folder and does not require administrator rights, so it usually succeeds even on a locked-down machine. If it is blocked anyway, do not lose a week over it — see section 8.

Ignore anything you read about WSL

Some guides tell Windows users to install Ollama inside WSL, a Linux layer. You do not need that and it will make things harder, because your Python is running in Windows and would then have to reach across into Linux. Use the ordinary .exe.

Open a terminal — press Cmd + Space, type Terminal, press Enterpress the Windows key, type PowerShell, press Enter — and check:

$ ollama --version
ollama version is 0.x.x

Any version number means you are fine. If you get command not found: ollamaollama : The term 'ollama' is not recognized, see section 7 — it is almost always a terminal that was already open before you installed.

3 · Confirm the server is running

This is the step people skip, and then spend an hour debugging Python for no reason. The best test does not involve the terminal at all. Open a browser tab:

http://localhost:11434
Ollama is running

Those three words mean everything downstream will work. If the page fails to load, open the Ollama app from Applicationsfrom the Start menu and try again.

About ollama serve — this one costs people an afternoon

Most guides on the internet tell you to run ollama serve and leave the window open. That advice is written for Linux. On macOS and Windows the desktop app has already started the server, so running the command yourself fails with:

Error: listen tcp 127.0.0.1:11434: bind: address already in use

That error is good news. It says something is already listening at that door, and that something is Ollama. Nothing is wrong. Close the message and carry on. Run ollama serve only if the browser test above failed and you cannot find the app.

4 · Choose a model

A model is one large file of learned numbers. Bigger models are cleverer, slower, and hungrier for memory. The name has two parts: llama3.2 is the family and :3b is the size — three billion parameters. Small, by current standards, which is exactly the point.

Lab · which size, and what it costs you

Move the slider to your laptop's memory. The bars show roughly how long one full run of the study takes — forty responses under two conditions, so eighty calls to the model. The red line is the point where a run stops fitting into an afternoon.

Why a deliberately small model is the right choice here

Worth being able to defend, because someone will ask.

It is the honest test case. If prompting alone lifts a three-billion parameter model's detection, that is a result a school could deploy on hardware it already owns. Showing that a frontier model can do it is a much weaker claim, and a much less useful one.

It is reproducible. A local model at temperature 0 gives you the same answer twice. A hosted API changes underneath you, and in six months nobody — including you — can reproduce the numbers.

It is private and free. No student writing leaves the machine, no key, no bill, and no rate limit when you rerun at eleven at night.

5 · Download it, then talk to it

$ ollama pull llama3.2:3b
pulling manifest pulling dde5aa3fc5ff... 100% ▕████████████████▏ 2.0 GB verifying sha256 digest writing manifest success

About 2 GB, so use decent wifi and give it several minutes. You do this once; the file stays on your disk. Confirm it landed:

$ ollama list
NAME ID SIZE MODIFIED llama3.2:3b a80c4f17acd5 2.0 GB 2 minutes ago
The name must match your config exactly

Whatever appears in that NAME column has to match MODEL_NAME in python/misconception/config.py, character for character, colon included. If you pulled the 1b, change the config rather than re-downloading. Mismatched names are the single most common cause of "model not found".

Now get a reply, before any Python

Debugging your code and your model install at the same time is miserable, because you never know which one is broken. Confirm the model alone works:

$ ollama run llama3.2:3b "Say hello in five words."
Hello, how are you today?

The first reply may take 10–30 seconds while the model loads into memory; after that it is quick. Running ollama run llama3.2:3b with no question gives you an interactive chat — type /bye to leave.

Try this one — it is directly about your study 
$ ollama run llama3.2:3b "A student says: 'A password with symbols in it can never be cracked.' Is that a misconception? Answer M or C."

Notice whether it answers with a clean M or wanders for a paragraph. That wandering is exactly why parse_verdict() in llm_client.py has four fallback strategies and can return ? rather than guess. Seeing it happen now makes the unparseable count in your Phase 5 results feel obvious rather than alarming — and that count is a real finding about small-model reliability, not an embarrassment.

6 · Connect it to the project

Run these 
$ cd path/to/SenSym-Misconceptions-Detailed/python
$ python3 misconception/check_setup.py

Type cd with a space, then drag the folder from Finder onto the Terminal window and it fills in the path.

In File Explorer, shift-right-click the folder and choose "Copy as path", then paste it after cd . If python3 is not recognised, use python.

The two lines you are looking for:

[OK] Ollama is running [OK] model 'llama3.2:3b' downloaded (you have: llama3.2:3b)

That is the finish line for this page. Anything still marked [TODO] — your two data files, most likely — is expected and not a problem; those are Phase 3. Only [FIX] means something is actually broken.

Then prove the whole pipeline runs, using the fake model and the twelve demo responses, so it takes a second and needs nothing from you:

$ python3 misconception/run_experiment.py --mock --sample
$ python3 misconception/analyze.py

Real charts appear in python/results/. Numbers from --mock or --sample never go into your write-up; they exist to prove the plumbing works.

7 · When it goes wrong

Symptom 7.1command not found

command not found: ollama or 'ollama' is not recognized

Diagnosis and fix

The terminal does not know where the program lives. In order of likelihood:

1. The terminal was open before you installed. A terminal learns about new programs only when it starts. Close the window completely and open a fresh one. This is the fix about four times out of five.

2. The app has never been launched. Open Ollama itself once from Applications — it installs the command-line tool on first run and asks permission to do sofrom the Start menu, then reopen the terminal.

3. Still stuck. Try the full path: /usr/local/bin/ollama --version. If that works it is a PATH problem, which takes two minutes to fix on a call.

3. Still stuck. Sign out of Windows and back in. That forces PowerShell to reload the PATH, which the installer changed.

Symptom 7.2cannot reach

Could not reach Ollama at http://localhost:11434/api/generate

Diagnosis and fix

Your Python knocked and nobody answered. The server is not running. Confirm with the browser test: go to http://localhost:11434 and look for "Ollama is running".

If the page does not load, open the Ollama app and confirm the llama appears in the menu barand confirm the llama appears in the system tray, possibly behind the ^ arrow. Then rerun check_setup.py.

Do not start by editing Python. This error is never caused by your code — it is caused by there being nothing to talk to. Knowing which layer an error lives in is most of what debugging is.

Symptom 7.3address in use

Error: listen tcp 127.0.0.1:11434: bind: address already in use

Diagnosis and fix

Nothing is wrong. You ran ollama serve while the desktop app was already running the server. The message means the door is already occupied — by Ollama.

Close it and move on. You never need ollama serve on macOSWindows. An error that means "the thing you wanted has already happened" is worth recognising on sight; you will meet the pattern again.

Symptom 7.4model not found

model 'llama3.2:3b' not found

Diagnosis and fix

The server is up but that file is not on disk, or the name does not match. Run ollama list and compare the NAME column against MODEL_NAME in python/misconception/config.py. They must match exactly.

If the list is empty, ollama pull llama3.2:3b. If you have a different size, change the config to match rather than downloading a second model — there is no reason to keep two.

Symptom 7.5slow

One answer takes minutes, or the whole laptop becomes sluggish.

Diagnosis and fix

The model does not fit in memory, so the machine is swapping to disk. Drop a size: ollama pull llama3.2:1b, then set MODEL_NAME = "llama3.2:1b" in config.py.

Also close the browser. Chrome and a language model are competing for exactly the same memory, and the browser usually wins. ollama ps shows what is currently loaded.

The smaller model is not a compromise on the science. A weaker model that benefits more from misconception-aware prompting is arguably the more interesting result — a bigger effect on a smaller base is exactly what you would predict if the catalogue is supplying knowledge the model lacks. You report which model you used and why, which you were going to do anyway.

Symptom 7.6unparseable

The model replies, but the predictions column is full of ?.

Diagnosis and fix

Not an install problem. The model is answering but not in the VERDICT: M format the prompt asked for, so parse_verdict() declines to guess and returns ?.

Two fixes, in order: make OUTPUT_FORMAT_INSTRUCTION in prompts.py blunter and more repetitive, or move up a model size.

But first, write the number down. "The 3B model produced unparseable output on 12% of items" is a genuine finding about small-model reliability and belongs in your results. Quietly defaulting those to C would make your numbers look better than they are, which is why the code refuses to do it.

8 · If Ollama will not install at all

A locked-down school laptop can beat you, and it is not worth a fortnight. The thing to internalise: Ollama is required for exactly one step of this project.

PhaseNeeds Ollama?
Python, the repo, the first runNo
Phase 2 — the six code TODOsNo — mock mode covers all of it
Phase 3 — writing your forty responsesNo
Testing the pipeline and the chartsNo — --mock --sample
Phase 4 — the one real runYes
Phase 5 — analysis and write-upNo

So build everything in mock mode and get access to one machine for one afternoon: a home computer, a family member's laptop, anything. Or say so and we will sort it out. Do not let this block you — the dataset you write in Phase 3 is worth far more of your time than the install is.

Going deeper (optional)

If you want to see what is actually going over the wire, Ollama's API is plain HTTP and you can hit it with anything. This is the same request llm_client.py makes:

$ curl http://localhost:11434/api/generate -d '{
  "model": "llama3.2:3b",
  "prompt": "Answer with one letter, M or C.",
  "stream": false,
  "options": {"temperature": 0}
}'

You get back JSON with a response field. That is the entire interface. Every "AI integration" you will ever read about is, underneath, a POST like this one — which is worth knowing the first time somebody tries to sell you a framework for doing it.
